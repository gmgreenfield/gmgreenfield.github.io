Hey, I’m Graham Greenfield. This site is a collection of notes, ideas, and writing about software development. When I want to understand a concept more deeply, work through an idea, or spend some time thinking about a problem, I tend to write a blog post about it.

My main interests these days are systems programming, BSD and GNU/Linux, cryptography, and LLMs, including their tuning and practical application. For the first ~12 years of my software engineering career, I primarily worked in web development, using Python, PHP, JavaScript, and even a bit of J2EE. I’ve spent enough time in the web world at this point that I’m quite happy to leave most CRUD applications behind.

I’m also interested in how AI and LLMs fit into software development. I think they can be genuinely useful tools — for example, as a kind of interactive documentation browser, or as a way to explore an idea, think through a design, or look at a problem from a different angle. At the same time, I think there’s an important distinction between using a tool to help you think and using it instead of thinking.

If an LLM helped write something, that’s fine; but the person responsible for the code should still be able to explain what it does, why it’s there, and why it was written that way. I’m interested in using these tools to become better at understanding and building software, rather than using them as a replacement for that understanding. I'm not really in favor of using Claude or Codex; When an LLM harness writes the file for you and immediately gives you a working solution, it creates this really tight dopamine loop: ask for something, watch it get built, see it work. I think there's a real risk that we start optimizing for that feeling instead of the process of actually figuring things out ourselves.

I’m not currently looking for work. I’m quite happy doing more systems-oriented development these days; I’m enjoying where that’s taking me.
